# 2026-09-17 afternoon: whole-tree review and fixes

A `/code-review max` over the whole tree at 84a5ecb, then every finding
fixed in one pass. 268 tests pass (was 234); a live `npm start` against the
real feeds answered in 2 s with every signal present.

## What changed and why

- **Server could be killed by one request.** `new URL(req.url)` ran outside
  any try/catch in the async listener; a request target llhttp accepts and the
  WHATWG parser rejects (`GET //[::1/verdict`) crashed the process before the
  key check. Now a 400, and the whole listener is guarded.
- **Optional feeds could reject before routing answered.** Their promises had
  no handler until after `computeOptions`, so a RangeError from the track-work
  parser (`&#1114112;` in a cell) was an unhandled rejection and Node exited.
  Every `fetchX` now catches everything; the engine guards them again.
- **No feed had a deadline.** `src/http.js` is the one JSON/text fetch helper
  (replacing six copies) and takes an AbortSignal; the engine gives each
  optional feed `SIGNAL_TIMEOUT_MS` (8 s), the sheet write `LOG_TIMEOUT_MS`
  (4 s), and Routes calls `ROUTE_TIMEOUT_MS` (12 s). A stalled vendor costs
  its signal, never the verdict.
- **DDOT envelope dropped.** The server-side ArcGIS envelope cost 6 to 7 s for
  the same 115 features the bare where clause returns in 0.3 s. The box is
  now applied client side, `exceededTransferLimit` is checked, and closures,
  CHART and incidents are fetched alongside routing and assessed afterwards
  (`loadX` then `assessX`).
- **Live incidents are matched to the route.** TomTom geometry is kept and
  `assessTrajectory` takes `points`; an accident across the District no
  longer says "crash ahead". Radius 120 m, point-to-segment
  (`polyline.nearPolyline`, shared by all three spatial feeds).
- **CHART gets rule 5.** Source: newest `lastCachedDataUpdateTime` in the
  current month, else stale. Record: `closureEndDate` in the past or a
  future start rules it out.
- **Config validates what it used to accept.** Unknown IANA zone, `nan`/`inf`,
  `assumed_evening_departure` not `HH:MM`, negative margin, quoted venue
  coordinates, out-of-range venue coordinates, and `transit.lines` not on
  WMATA's list are all startup errors. Line names are canonicalised
  (`"red"` -> `Red`).
- **One penalty per missing key.** `TRANSIT_API_KEY` is out of `SECRETS`
  (nothing reads it; its presence was worth 0.1 confidence). Incidents run
  without a key too and report `no TRAFFIC_API_KEY` as their own unknown;
  the engine passes no `degraded` list to `decide()`.
- **Events partial failure is unknown when the answered sources found
  nothing** (rule 4); a positive finding from the source that did answer is
  still spoken. `partial` is set either way.
- **Spoken order.** `decide()` builds core, then findings, then caveats, so a
  crash is heard before "no X data" or "it is a close call". The unstable
  clause folds its incident descriptions in. `roadUnstable` is null when the
  lookup failed. The spoken saving is the difference of the spoken minutes.
- **Log columns are fixed.** `EXTRA_COLUMNS` and `FULL_HEADER` in `src/log.js`;
  an unlisted extra throws. `ensureHeader` reads row 1, extends a header that
  is a prefix of `FULL_HEADER` (the live tab, 47 cells) and refuses any
  other. Two new columns: `transit_walk_seconds`, `incidents_route_matched`.
  `bq-external-table.sh` builds from `FULL_HEADER`. `tokenProvider` receives
  the injected fetch, so `npm test` no longer touches the metadata server.
- **Server logs `log failed: ...`** and returns `logged` in the body.
- Smaller: Routes wraps fetch rejections and non-JSON as `RouteError`;
  `--from=origin` and unknown CLI arguments; entry guards use realpath;
  deploy script refuses an empty `op read` (a failed read used to leave a
  versionless secret); open-ended track-work rows ("Until further notice")
  stay active 90 days; numeric entities outside Unicode are left as written;
  empty DDOT date strings are null, not 1970.
